# Midjourney 参数指南

这些值来自鲲鹏风格库的实际出图经验，是可靠起点，不是某个客户端或服务的固定接口契约。真正提交任务前，由用户或调用方按其自行配置的客户端文档确认模型 ID、参数名和范围。

## 三种工作模式

| 模式 | 初始值 | 适用场景 |
| --- | --- | --- |
| faithful | stylize 140, chaos 0, raw on | 人物身份、产品结构、纪实摄影、严格构图 |
| balanced | stylize 300, chaos 0, raw off | 常规视觉开发、电影感、东方美学 |
| exploratory | stylize 300, chaos 25, raw off | 概念探索、构图发散、材料实验 |

风格预设的参数优先于模式初始值；用户明确指定的参数优先级最高。

## 常用调整

- 更真实、少 AI 感：开启 raw，stylize 调到 80–160，chaos 保持 0。
- 更艺术、更华丽：stylize 增加 100–150，通常不超过 500。
- 多个明显不同方向：chaos 调到 20–30；不要误把 chaos 当成画质增强。
- 保持主体与构图：chaos 0，stylize 不高于 150；若客户端支持，再固定 seed。
- 产品、UI、标志：stylize 0–80，chaos 0，明确结构与留白。
- 怪诞实验：仅在用户明确要求时使用 weird 100–300。

## 版本与参数兼容

- V8.2 是本 Skill 的默认版本。
- V8.2 不应沿用旧版 `quality/q` 参数；部分客户端会直接拒绝。
- Niji 风格使用当前客户端支持的 Niji 模型或对应参数，不要同时拼普通 `--v` 与 `--niji`。
- 如果调用方提供结构化 `aspect_ratio`、`stylize`、`chaos`、`raw` 字段，就不要在 prompt 中重复写 flags。
- 如果客户端只接受命令文本，再把结构化参数编译为 `--v`、`--ar`、`--stylize`、`--chaos`、`--style raw`。

## 参考图角色

不要把所有参考图都当成同一种输入：

- 内容参考：约束人物、物体、构图或场景。用 image weight 控制影响。
- 风格参考：只传递色彩、材质、光线和视觉机制。用 style reference 与 style weight。
- 两者兼有：必须先说明哪张图保护主体，哪张图只提供风格，避免风格母图改变人物或产品结构。

使用参考图时，正文仍描述最终画面，不写“参考图片一”“把图改成”等过程性语言，除非具体客户端要求索引语法。
